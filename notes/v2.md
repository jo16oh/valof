# valof v2 の API

結論だけ。経緯と却下案は `design.md` §15 にある。

`Trait` は実装済み（PoC）。`Enum` と `path` は未着手。**順番は Enum が先**（Variant への focus が `path` の
設計に効くため）。

---

## Trait

`design.md` §15.1。

```ts
type Greetable = Trait<
  "Greetable",
  { name: string },
  {
    greet: (self: Self) => string;
    shout: Final<(self: Self) => string>;
  }
>;

const Greetable = Trait.companion<Greetable>().impl({
  greet: (g) => `Hi, ${g.name}`, // 既定。implTrait で上書きできる
  shout: (g) => g.name.toUpperCase(), // Final。できない
});

type User = Val<"User", { id: string; name: string }, Greetable>;

const User = Val.companion<User>().implTrait(Greetable, {
  greet: (u) => `Sir ${u.name}`, // 上書き
});

User.greet(user);
Greetable.shout(user); // 名前空間に出るのは Final だけ
Greetable.dyn(User, user).greet(); // 箱
```

- **メンバは 1 種類。**trait の `.impl` が既定を配り、`implTrait` が任意の部分集合を上書きする
- **`Final` は宣言側のマーカー。**実行時に消える。上書きの禁止だけが目的
- **`dyn` は trait の名前空間に置く。**`Greetable.dyn(User, u)`。単独 export にすれば 54 B 落とせるが、
  読みやすさを取った

## Enum

`design.md` §15.2。

```ts
type Shape = Enum<"Shape", { Circle: { r: number }; Square: { side: number } }, "kind">;

const Shape = Enum.companion<Shape>("kind");
const { Circle, Square } = Shape;

Shape.match(shape, { Circle: (c) => c.r * 2, Square: (s) => s.side });
```

- **Variant をレコード 1 つに宣言して union を導出する。**手書きの union だと Variant 追加時に 2 箇所直す
- **Variant は個別に Val。**ブランドは交差（§15.1 と同じ形）で、文字列は `"Shape.Circle"` を**導出**する
- **タグ名は型引数で変えられる。**既定は `"_tag"`。タグは実データで境界を越えるので、名前は valof が
  決めるものではない。実行時にも要るので `Enum.companion` の引数と二重になり、valof-lint の `tag-mismatch`
  が守る（`brand-mismatch` と同じ形）
- **`match` は companion に置く。**カスタムのタグ名を自由関数からは読めない。名前空間つきの関数整理
  （`positioning.md` §1-2）とも揃う
- **`match` はカリー化しない。**両方とも値なので 1 回で推論できる
- **ガード節は ts-pattern に任せる。**タグで分けるだけなら `match`、条件が要るなら ts-pattern
- **Trait との違いは開閉。**Trait は開いた集合、Enum は閉じた集合。両方あって重複しない

## path

`design.md` §15.3。`patch` が Val の境界で止まる（§6.8）ので、境界をまたいで合成する。

```ts
const managerWallet = path(Team).manager(Manager).wallet(Wallet);

managerWallet.glue(neverthrow).patch(team, { balance: 5 }); // Result<Team, E1 | E2>
managerWallet.glue(neverthrow).update(team, (w) => ({ balance: w.balance * 2 }));

path(List)
  .items.each(Todo)
  .where((t) => t.done)
  .glue(g)
  .patch(list, { archived: true });
```

### 規則

- **値は最後に取る。**`path(Team)` から始めるので経路が値になり、再利用できる
- **各段で companion を書く。**フィールド名から companion を引く方法が無い。宣言 1 回に集まる
- **`abort()` は `path` の語彙。**seal の契約は変わらない。seal は今までどおり利用者の Result を返す
- **`glue` は最終段。**早く束縛すると利用者の Result 型構築子について総称になり、HKT が要る

### glue

```ts
export const neverthrow = {
  open: (r) => (r.isErr() ? abort(r.error) : r.value), // Result → V | Abort
  close: (v) => (isAbort(v) ? err(v.error) : ok(v)), // V | Abort → Result
};
```

- **1 つのオブジェクトで両方向。**半端に変換された値が出る事故が起きない
- **`close` は optional。**渡さなければ `V | Abort<E>` の union が返る
- **既製版をサブパスで配る。**`valof/neverthrow` など。コアは Result を知らないまま
- **失敗しない経路では包まない。**経路上に `implSeal` が 1 つも無ければ素の値が返る

### 操作

判定基準は「深さ」ではなく **「seal が絡むか」**。

|                 | 入れる | 理由                                                                     |
| --------------- | ------ | ------------------------------------------------------------------------ |
| `patch`         | ○      |                                                                          |
| `update(v, fn)` | ○      | 各段の seal を積み直す必要が出る。§6.4 と同じ「値 → 値」なので名前を統一 |
| `each`          | ○      | seal が失敗しうると `Result<Todo>[]` の畳み込みになる                    |
| `where`         | ○      | `each` の後ろでのみ。一致が無ければ何もしない                            |
| `get`           | ✗      | 素のプロパティアクセスで足りる。足すと optics の階層が始まる             |

### 経路は companion に置ける

経路は値なので `.impl` に入る。第 1 引数が根の Val なので §6.5 の規則にそのまま合う。

**置き場所は根の companion で決まる。**別の Val を第 1 引数に取る関数は `.impl` が弾くので、特別な規則が
要らない。根は必ず定義中の companion になるため、経路は関数の中で組む（`design.md` §15.3）。

```ts
const Team = Val.companion<Team>().impl({
  raiseManager: (t, n) =>
    path(Team).manager(Manager).wallet(Wallet).glue(g).patch(t, { balance: n }),
});
```

### 型で塞げない穴

**ハンドラの各段の対応を型が要求できない。**要求するには HKT が要る。lint も無理。

**穴の形は良い。**ハンドラはプロジェクトで 1 つ、1 行、`path` の全経路がそこを通る。既製の glue を配れば
大半の人には届かない。

### 着手前に測る

1. パス型と Err 収集型が宣言の予算に入るか（30.04 / 32.00 kB、残り 6%）
2. `glue` の union ハンドラの推論が通るか

## `.impl` のコールバック形

`design.md` §15.4。`.impl` がオブジェクトに加えて関数も取る。引数はその時点で決まっている関連関数で、
分割代入で要るものだけ受け取る。

```ts
Val.sealer<User>().impl(({ equals, patch }) => ({
  same: (u, other: User) => equals(u, other),
  renamed: (u, name: string) => patch(u, { name }),
}));
```

- **動機**: 自分の companion を `.impl` の中で参照すると推論が回らない（TS7022）。今は戻り値の注釈で回避
  する。コールバックは循環を切る
- **第 1 引数の contextual typing は効く**（実測済み）
- **兄弟メンバは参照できない。**同じ `.impl` の中の他のメンバは循環したままなので注釈が要る
- **オブジェクト形は残す。**関連関数が要らないメンバに分割代入は雑音
- 渡す集合が `sealer` / `companion` / `implTrait` の有無で変わるので、宣言の予算を測ってから
